# Правила ревью PR

## Главное правило
PR должен быть в статусе **Draft** пока он не готов к ревью.

## Когда PR готов к ревью?
1. Код полностью работает
2. Нет конфликтов с `dev`
3. Проходят все линтеры
4. Обновлена документация (если нужно)

## Кто должен проверить PR?
Нужны **два** апрува:
1. От QA - проверяет UI/UX
2. От разработчика - проверяет код

## Процесс
1. Делаете PR в статусе Draft
2. Когда всё готово:
   - Переводите из Draft в Ready
   - Назначаете ревьюеров
3. Если потребовались правки - возвращаете в Draft
4. Два апрува - происходит мерж

## Шаблон PR
```markdown
## Что сделано
Кратко что изменилось

## Как проверить
1. Открыть страницу X
2. Нажать Y
3. Должно произойти Z
```
